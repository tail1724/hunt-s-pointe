Diagnosis

Three failure modes, one root cause

The backend RAG pipeline is sophisticated — hybrid retrieval, HyQE, parent expansion, citation verification. The frontend doesn't expose any of that work. Users see a text wall that appears all at once, scrolls sluggishly, and hides its own artifacts.

Root cause: The streaming UI is a presentation layer bolted onto a research-grade retrieval system. The pipeline produces structured, multi-modal knowledge; the frontend discards the structure and renders plain prose.

PipelineIndicator — replace ThinkingTrace

The current MaryThinkingTrace cycles random phrases from t=0. Upgrade it to a state machine driven by actual __nexus events so what the user reads is true:

type PipelineState =
  | 'condensing'   // before first __nexus event
  | 'retrieving'   // after retrieval_start, arms = n
  | 'reading'      // after retrieval_done, before first token
  | 'streaming'    // first token received
  | 'verifying';   // after [DONE], before citation result

// In useMaryChat — emit these via a pipelineState setter driven by __nexus
if (sig.type === 'retrieval_start') {
  setPipelineState({ stage: 'retrieving', armCount: sig.arms });
}
Why this matters: "Searching 2 sources from your Luke 15 notes" is demonstrably more informative than "Weighing a stronger verb…". It shows the system doing real work, not performing thinking theater.
Blueprint · C

Virtualized message list

Long sessions currently mount every message in the DOM — prose ASTs, ScriptureArtifacts, InlineDocumentCards — all simultaneously. Beyond ~30 turns the scroll jank is measurable. Virtual scroll fixes this without architectural surgery.

Implementation: @tanstack/react-virtual

// src/components/mary/VirtualThread.tsx
import { useVirtualizer } from '@tanstack/react-virtual';

const virtualizer = useVirtualizer({
  count: messages.length + (isLoading ? 1 : 0),
  getScrollElement: () => scrollRef.current,
  // Estimated height: user bubble ~48px, assistant response ~280px.
  estimateSize: (i) => messages[i]?.role === 'user' ? 64 : 300,
  // Measure actual DOM height after render so scroll is accurate.
  measureElement: (el) => el?.getBoundingClientRect().height ?? 300,
  overscan: 3,
});

Scroll anchoring

Virtual lists don't auto-scroll. Replace the current bottomRef.scrollIntoView with scroll-to-index:

// Scroll to last item whenever message count increases.
useEffect(() => {
  if (messages.length > 0) {
    virtualizer.scrollToIndex(messages.length - 1, {
      align: 'end', behavior: 'smooth',
    });
  }
}, [messages.length]);

Stable keys

Virtual lists need stable item identities. The current key={i} (array index) causes unnecessary remounts. Assign each message a UUID at creation time and key by that.

Multi-modal layout — Artifact Rail

Non-text artifacts (transcribed audio, chart data, captioned images) should not interrupt reading flow. The thread stays prose-focused; artifacts surface in a contextual side rail triggered by inline chips.

Artifact chip → rail bridge

Inline text renders an ArtifactChip wherever a non-text slot was parsed. Clicking it opens or highlights the corresponding card in the rail. On mobile, chips trigger a bottom sheet.

// ArtifactChip — inline in thread prose
<ArtifactChip
  icon="🎵"
  label="Transcript · 2:14"
  onClick={() => railDispatch({ type: 'focus', artifactId })}
/>

Rail state

The rail accumulates artifacts across the entire session, not just the current message. It's a scratchpad: pinnable, reorderable. A session that analyzes a video and two PDFs ends up with a consolidated artifact workspace.

Performance

Latency mitigation — four wins

Each of these is implementable independently. Combined, they eliminate the perceived lag even when the RAG pipeline itself takes 2–3 seconds.

  • 1
    Surface pipeline telemetry as staged UI copy Wire the existing __nexus preamble events into PipelineIndicator. "Searching 3 sources in your Luke 15 collection…" changes the wait from opaque to transparent. Users tolerate latency they can observe far better than latency they can only feel. Estimated perceived-latency reduction: 40–60%.
  • 2
    Defer artifact mounting until stream ends Mount InlineDocumentCard, TranscriptCard, and ChartCard only after isLoading flips false. During streaming, render a SkeletonBlock type="card" placeholder at the artifact position. This keeps the compositor budget free for the typewriter animation — the part the user is actively watching.
  • 3
    Virtual scroll with dynamic measurement Install @tanstack/react-virtual with measureElement. Cap rendered DOM nodes at ~200 regardless of session length. This is the single highest-impact change for long-session users — the scroll jank is proportional to message count, and it compounds quickly above 30 turns.
  • 4
    CSS paint isolation on streaming cells Add contain: layout style to message list items. Add will-change: transform to the scroll container only (not individual cells — promotes too many layers). Remove box-shadow from elements during streaming; apply it via a class toggle after stream ends. These are compositable properties — the browser doesn't repaint the whole thread on each token.
Performance

Animation & paint budget

The typewriter drain loop already runs on requestAnimationFrame. Everything else should stay out of its way — no layout-triggering properties during streaming, no heavy shadows on animated elements.

ElementAnimationPropertyDuration
Message enter Fade + rise opacity, translateY(8px→0) 200ms ease-out
Typewriter Character reveal Text node mutation via RAF Continuous (~22ms/tick)
Artifact reveal Unmask + scale opacity, scale(0.98→1) 250ms, staggered 180ms
Citation badge Fade in opacity 150ms after verify response
PipelineIndicator Stage text crossfade opacity 120ms on each state transition
Rail slide-in Expand width / max-width 220ms ease-out
Reduced motion: Every animation above checks prefers-reduced-motion. When set, transitions are disabled and typewriter speed doubles (content appears faster, not animated). This is already implemented in the drain loop — extend the pattern to all new animations.
What not to animate: Scroll position, height changes during streaming, box-shadow during active RAF loops. These trigger layout recalculation on every frame and are the primary cause of jank in streaming chat UIs.
